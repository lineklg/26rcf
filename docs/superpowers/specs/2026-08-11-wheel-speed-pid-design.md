# 四轮 PID 速度环设计

## 目标

在 `Core/User` 下新增四轮 PID 速度环模块，使 `Wheel_Forward()` 和
`Wheel_Turn()` 的参数表示车轮线速度，单位为 m/s。四个轮子分别使用编码器
反馈和独立 PID 调节器，PID 输出作为 DRV8870 的归一化占空比。

## 方案选择

采用现有 `User/pid.c` 的 `PID_Manager`。新模块创建四个 PID，并在
`wheel_pid.c` 中提供 `PID_Task()` 的强定义，覆盖通用模块中的弱定义。
这样可以保持现有 PID 创建、周期设置、启停和计算接口不变。

本实现不采用独立任务或在 `behavior.c` 内直接编写控制算法。PID 全局任务由
四轮速度环使用；若后续其他机构也需要周期 PID 控制，应重新设计统一的
`PID_Task()` 调度职责。

## 文件与职责

新增 `Core/User/wheel_pid.h` 和 `Core/User/wheel_pid.c`。

`wheel_pid.h` 采用与 `behavior.h` 一致的简单头文件结构，声明速度环初始化、
四轮目标速度设置、单轮 PID 参数设置、启动和停止接口。新增 C/C++ 声明使用
中文 Doxygen 注释，文件编码为 UTF-8。

`wheel_pid.c` 保存四个 PID 指针、四个目标速度、四个 `Motor` 对象和四个
`DRV8870_Motor` 对象的引用，以及速度环运行状态。模块提供 `PID_Task()` 的
强定义，每次运行依次完成四轮测速、PID 计算和占空比输出。

`behavior.c` 仅接入上述接口，不新增注释。`CMakeLists.txt` 显式加入
`Core/User/wheel_pid.c`，`Core/User/user.h` 引入新模块头文件。

## 初始化

`User_Init()` 先调用 `Task_Init()`，再调用 `Wheel_Init()`，保证 PID 周期任务
创建时任务管理器已经可用。

`Wheel_Init()` 保留现有四路 DRV8870、编码器和 `Motor` 初始化，随后调用
速度环初始化。速度环初始化执行以下操作：

1. 调用 `PID_Init()`，创建休眠状态的 20 ms PID 周期任务。
2. 通过 `PID_Create()` 创建四个 PID。
3. 四轮默认参数统一为 `Kp=1.0f`、`Ki=0.0f`、`Kd=0.0f`。
4. 每个 PID 的输出绝对值上限设置为 `1.0f`。
5. 目标速度清零，PID 历史清零，任务保持休眠。
6. 四路驱动进入制动状态。

`Wheel_Init()` 只在系统初始化阶段调用一次。再次调用 `PID_Init()` 会清空
PID 管理器，因而不支持运行期间重复初始化。

## 运动数据流

`Wheel_Forward(speed)` 将 A、B、C、D 四轮目标速度均设为 `speed`。

`Wheel_Turn(speed)` 将 A、C 轮目标速度设为 `-speed`，将 B、D 轮目标速度
设为 `speed`，保持现有原地转向方向。

设置目标后，若速度环处于停止状态，则清除四个 PID 的历史并调用
`PID_Start()`。若速度环已经运行，则仅更新目标值，不重置积分或重新安排任务
运行时刻。

每次 `PID_Task()` 执行时，对每个轮子依次调用：

1. `Motor_CalcSpeed_Smooth()` 获取 m/s 单位的平滑反馈速度。
2. `PID_Calc()` 根据对应目标速度和反馈速度计算控制输出。
3. `DRV8870_SetDutyPercent()` 将限制在 `-1.0f` 到 `1.0f` 的输出写入驱动。

四个 PID 使用相同默认参数，但可通过轮号分别修改 `Kp`、`Ki` 和 `Kd`。
无效轮号不修改任何 PID。

## 停止语义

`Wheel_Stop()` 必须按照以下顺序执行：

1. 调用速度环停止接口，使 PID 周期任务立即休眠。
2. 将四轮目标速度清零。
3. 分别清除四个速度 PID 的积分和上次反馈历史。
4. 对四路 DRV8870 调用 `DRV8870_Brake()`。

停止任务必须先于制动，避免任务在停止过程中再次写入占空比。下一次调用
`Wheel_Forward()` 或 `Wheel_Turn()` 时，速度环从清空后的历史自动恢复运行。

## 异常与边界

PID 输出由通用 PID 模块限制在 `-1.0f` 到 `1.0f`，DRV8870 驱动仍保留自身限幅作为
第二层保护。无效轮号设置请求直接忽略。初始化时若 PID 容量不足，对应指针
保持为空；周期任务跳过未成功创建的 PID，避免解引用空指针。

本次不增加速度目标上限、堵转检测或编码器故障检测。这些功能需要基于实车
参数另行设计。

## 测试与验收

新增主机侧测试，使用真实 PID 计算代码并以桩函数记录四路驱动输出。测试
覆盖以下行为：

- 初始化创建四个独立 PID，默认任务不产生驱动输出。
- 前进命令为四轮设置相同目标速度。
- 转向命令为 A/C 与 B/D 设置相反目标速度。
- 四个反馈值分别参与对应 PID 计算，不串用状态。
- PID 输出限制在 `-1.0f` 到 `1.0f`。
- 运行中改变目标不会清除 PID 历史。
- `Wheel_Stop()` 后周期调度不再写入驱动，并且四路立即制动。
- 停止后重新启动使用已清除的 PID 历史。
- 无效轮号不会改变有效轮子的 PID 参数。

实现完成后运行新增主机测试、现有主机测试和 STM32 Debug 构建。验收标准为
测试全部通过，交叉编译成功且不新增编译警告。
