# USB VPC 接收环形缓冲区设计

## 目标

将 `usb_fs_vpc` 中公开的 512 字节接收数组改为模块私有环形缓冲区，并提供明确的写入、读取接口。缓冲区用于 USB CDC 接收回调向主循环传递字节流。

## 接口

```c
uint32_t USB_VPC_RxWrite(const uint8_t *data, uint32_t len);
uint32_t USB_VPC_RxRead(uint8_t *data, uint32_t len);
```

- `USB_VPC_RxWrite` 在剩余空间足够时写入全部 `len` 字节并返回 `len`。
- 写入空间不足时整包拒绝，返回 `0`，缓冲区内容和位置不变。
- `USB_VPC_RxRead` 最多读取 `len` 字节；数据不足时读取全部可用数据并返回实际长度。
- 空缓冲区读取返回 `0`。
- `data` 为空或 `len` 为 `0` 时，两种操作均返回 `0` 且不改变状态。

## 数据结构与并发模型

模块内部保存 512 字节数组以及单调递增的读、写位置。可用数据量为写位置减读位置，可用空间为容量减可用数据量；访问数组时对位置按容量取模，因此 512 字节容量可以全部使用。

并发模型限定为单生产者、单消费者：USB CDC 接收回调是唯一写入者，主循环是唯一读取者。写入者完成数据复制后才发布写位置，读取者完成数据复制后才发布读位置。位置变量使用适合 STM32H7 原子访问的 32 位类型并声明为 `volatile`，保持编译器层面的访问顺序。接口不支持多个写入者或多个读取者并发调用。

32 位位置自然回绕时，无符号减法仍能计算占用量；前提是生产者不会领先消费者超过缓冲区容量，该前提由拒绝超容量写入保证。

## 数据流

写入和读取都可能跨越数组末尾。实现将复制拆成尾部连续段和数组起始段，最多调用两次 `memcpy`。只有完整复制完成后才更新对应位置，消费者不会看到尚未复制完成的数据，生产者也不会覆盖尚未读取的数据。

本次不修改 CubeMX 生成的 `CDC_Receive_HS()`。接收回调后续可将收到的 `Buf` 和 `Len` 传给 `USB_VPC_RxWrite`，并根据返回值判断整包是否进入缓冲区。

## 错误处理

接口使用返回的字节数表达结果，不引入阻塞或额外错误码。空间不足与无效参数均返回 `0`；调用者若需要区分原因，应在调用前验证参数。缓冲区满时保留较早数据，不覆盖、也不部分写入新数据。

## 测试与验证

新增主机测试覆盖：

- 普通写入和读取；
- 数据不足时的部分读取；
- 数组尾部回绕后的顺序；
- 写满全部 512 字节；
- 空间不足时整包拒绝且已有数据不变；
- 空缓冲区读取；
- 空指针和零长度参数；
- 交错读写释放空间后的再次写入。

测试先以缺少接口或行为不符的方式失败，再实现最小代码使其通过。最后运行主机测试并构建 STM32 固件，检查接口声明、源文件依赖和交叉编译结果。
