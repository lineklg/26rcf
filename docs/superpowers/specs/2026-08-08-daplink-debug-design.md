# DAPLink Debugging in STM32CubeIDE for VS Code

## Goal

Enable this STM32H723ZGTx CMake project to build and debug from STM32CubeIDE for VS Code using a CMSIS-DAP compatible DAPLink probe over SWD.

## Context

- The project is generated by STM32CubeMX and uses the STM32CubeIDE for VS Code CMake integration.
- The target is STM32H723ZGTx (Cortex-M7).
- PA13/JTMS-SWDIO and PA14/JTCK-SWCLK are already configured as Serial Wire pins in `26rcf.ioc`.
- The existing Debug artifact is `build/Debug/26rcf.elf`.
- OpenOCD and Arm GDB are available on the development machine; pyOCD is not currently available.

## Chosen Approach

Use VS Code Cortex-Debug with OpenOCD as the GDB server:

1. A VS Code task configures/builds the Debug CMake preset.
2. A Cortex-Debug launch configuration starts OpenOCD with `interface/cmsis-dap.cfg` and `target/stm32h7x.cfg`.
3. OpenOCD uses SWD transport and a conservative adapter speed suitable for DAPLink.
4. Cortex-Debug loads `build/Debug/26rcf.elf`, resets the MCU, and runs to `main`.
5. Tool paths remain overridable through VS Code settings/environment so the project is portable across STM32CubeIDE installations.

## Files and Responsibilities

- `.vscode/tasks.json`: Debug configure/build task used before launching.
- `.vscode/launch.json`: DAPLink/CMSIS-DAP Cortex-Debug launch configuration.
- `.vscode/settings.json`: Optional path overrides for OpenOCD and Arm GDB, without disturbing existing Cube tooling settings.

No firmware source or CubeMX peripheral configuration changes are required. SWD remains enabled by the existing IOC configuration.

## Runtime Flow

```text
VS Code debug start
  -> build Debug preset
  -> start OpenOCD (CMSIS-DAP + SWD + STM32H7)
  -> connect Cortex-Debug via GDB
  -> load ELF and reset target
  -> stop at main
```

## Error Handling

- If CMake or Ninja cannot build, the pre-launch task stops the debug session before starting OpenOCD.
- If no DAPLink probe is connected, OpenOCD reports the connection failure in the Debug Console.
- If OpenOCD/GDB is installed outside PATH, the launch uses configurable VS Code settings rather than silently selecting an unrelated executable.
- The default adapter speed is intentionally moderate; it can be overridden in the launch configuration if the board and probe support a higher rate.

## Verification

- Run the existing Debug CMake build and confirm `build/Debug/26rcf.elf` is produced.
- Validate the launch/task JSON syntax.
- Run OpenOCD in a non-invasive configuration check to confirm both CMSIS-DAP and STM32H7 scripts resolve.
- With hardware connected, start the VS Code debug profile and confirm the target halts at `main` and accepts breakpoints.

## Non-Goals

- Installing or packaging pyOCD.
- Changing the generated CubeMX source or linker layout.
- Adding ST-LINK-specific configurations.
